Assessment surface

What gets tested

Commercial scopes are tailored to the target. The public demo describes categories rather than publishing reusable exploit payloads.

Instruction handling

Conflicting and adversarial instructions

Evaluate whether the application preserves intended instruction hierarchy and refuses unauthorized behavioral overrides.

Grounding

Unsupported claims and hallucination

Test whether the system distinguishes available evidence from inference, uncertainty, and missing information.

Data boundaries

Sensitive information handling

Assess whether the application respects configured data-access and disclosure boundaries within the authorized test environment.

Tool behavior

Agent and action constraints

Review whether tool-using workflows stay within their intended permissions, confirmation gates, and operational scope.

Robustness

Edge cases and prompt ambiguity

Probe brittle behavior, ambiguous objectives, and conditions where response quality or policy adherence degrades.

Decision quality

Uncertainty and risk communication

Check whether high-impact outputs communicate uncertainty, assumptions, counterarguments, and revision triggers appropriately.

Workflow

From scope to remediation

01 SCOPE

Confirm authorization, target boundaries, success criteria, exclusions, and reporting needs.

02 TEST

Execute agreed model-behavior and adversarial test categories against the authorized target.

03 ANALYZE

Separate reproducible behavior from one-off output, score impact, and document evidence.

04 REMEDIATE

Deliver practical fixes, residual-risk notes, and retesting where the engagement includes it.

What a finding looks like

This is a fictional public-safe example showing assessment structure. It is not a real client finding and does not disclose a reusable attack payload.

Medium · Example only

Instruction-boundary degradation under conflicting context

Observed behavior: the fictional assistant follows a lower-priority contextual request after repeated contradictory framing.

Risk: downstream applications that rely on stable instruction hierarchy could produce behavior outside the operator's intended control surface.

Confidence: moderate in this fictional example; reproducibility would require multiple controlled runs.

Evidence and remediation format

  • Test ID: DEMO-RT-001
  • Target: fictional sandbox assistant
  • Expected: preserve configured instruction hierarchy
  • Observed: lower-priority context influenced final behavior
  • Reproduction: payload withheld from public demo
  • Remediation: strengthen instruction isolation, validate trusted context boundaries, add regression tests for conflicting-context cases
  • Retest trigger: rerun the same category after mitigation
